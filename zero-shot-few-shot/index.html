Zero-Shot & Few-Shot Prompting: cuándo usar cada técnica

Una guía visual para elegir entre pedir una tarea directamente o enseñar el patrón con ejemplos. La clave no es memorizar nombres: es saber cuánto contexto necesita el modelo para responder bien.

Zero-shot
Pides la tarea sin ejemplos previos.
Few-shot
Das ejemplos para fijar formato, tono o criterio.
Uso ideal
Clasificar, resumir, transformar o generar contenido.
Regla práctica
Empieza simple; agrega ejemplos si la salida varía.
⚡
Idea central: Zero-shot funciona cuando la instrucción es clara y el resultado esperado es común. Few-shot ayuda cuando necesitas consistencia, estilo, estructura o criterios difíciles de explicar solo con palabras.

Resumen claro

Dos formas de darle contexto al modelo

Ambas técnicas son útiles. La diferencia está en cuánta demostración necesita el modelo antes de ejecutar la tarea.

Zero-shot

Instrucción directa

El modelo recibe la tarea y responde sin ejemplos. Es rápido, limpio y suficiente para tareas estándar.

Bueno para preguntas claras.
Útil cuando el formato no es delicado.
Ideal para primeras iteraciones.
Few-shot

Aprendizaje por demostración

El prompt incluye ejemplos de entrada y salida para que el modelo copie el patrón de respuesta.

Bueno para formatos específicos.
Útil cuando importa el tono.
Reduce variabilidad en tareas repetibles.
Combinación

Empieza simple, sube precisión

Un buen flujo suele empezar con zero-shot. Si la salida no cumple, conviertes el prompt en few-shot con ejemplos representativos.

Primero prueba intención.
Luego ajusta estructura.
Finalmente fija criterio con ejemplos.
Anatomía del prompt

Qué cambia dentro del prompt

La diferencia no está en usar palabras sofisticadas. Está en pasar de una instrucción aislada a una instrucción acompañada por ejemplos.

Zero-shot

Prompt sin ejemplos

Rol: Actúa como editor técnico.

Tarea: Resume el siguiente texto para una audiencia no técnica.

Formato:
- 5 viñetas
- lenguaje claro
- sin jerga innecesaria

Texto: [pegar contenido aquí]
Few-shot

Prompt con ejemplos

Rol: Actúa como clasificador de tickets.

Ejemplo 1:
Entrada: "No puedo iniciar sesión"
Salida: Acceso / Alta prioridad

Ejemplo 2:
Entrada: "Quiero cambiar mi plan"
Salida: Facturación / Media prioridad

Ahora clasifica:
Entrada: "[nuevo ticket]"
Comparación útil

Zero-shot vs Few-shot, sin humo

La elección depende de la dificultad del patrón, no de cuál técnica “suena más avanzada”.

Dimensión Zero-shot Few-shot Lectura práctica
Contexto inicial Solo instrucción Instrucción + ejemplos Few-shot da más señales sobre el resultado esperado.
Velocidad Más rápido de escribir Requiere preparar ejemplos Zero-shot gana cuando necesitas explorar rápido.
Consistencia Puede variar más Más estable Few-shot conviene cuando la salida debe repetir patrón.
Formato Sirve si el formato es simple Fija estructura con más claridad Los ejemplos reducen ambigüedad.
Costo del prompt Más corto Más largo No agregues ejemplos si no aportan precisión.
Uso ideal Resumen, explicación, primera versión Clasificación, estilo, extracción, plantillas Usa el nivel mínimo de contexto que funcione.
Marco de decisión

Cómo elegir en 5 pasos

Este flujo evita sobre-diseñar prompts. No todo necesita ejemplos; pero algunas tareas se vuelven mucho mejores con ellos.

01

Define la tarea

¿Quieres resumir, clasificar, transformar, extraer o generar?

02

Prueba zero-shot

Empieza con rol, tarea, formato y contenido. Observa la salida.

03

Detecta variación

Si el modelo cambia tono, criterio o estructura, falta demostración.

04

Agrega ejemplos

Incluye 2–4 ejemplos buenos, variados y representativos.

05

Evalúa salida

Si mejora, conserva el patrón. Si no, ajusta ejemplos o reglas.

Usa zero-shot cuando: la tarea sea común, el formato sea simple, el error sea barato o estés explorando una primera versión.
Usa few-shot cuando: necesites consistencia, clasificaciones delicadas, tono específico, extracción estructurada o ejemplos de “lo correcto”.
Casos de uso

Ejemplos listos para adaptar

Estos bloques muestran cómo pasar de una solicitud directa a una solicitud con patrón demostrado.

Educación

Explicar un concepto

Zero-shot funciona bien cuando solo necesitas una explicación clara.

Prompt: Explícame la diferencia entre mitosis y meiosis en lenguaje simple. Usa una tabla corta y termina con 3 preguntas de repaso.
Soporte

Clasificar tickets

Few-shot ayuda a fijar categorías y prioridad cuando hay ambigüedad.

Prompt: Ejemplo: "Mi factura llegó duplicada" → Facturación / Media "El sistema no abre" → Incidente técnico / Alta Clasifica: "[ticket nuevo]"
Contenido

Imitar estructura editorial

Cuando el estilo importa, los ejemplos suelen enseñar mejor que una descripción larga.

Prompt: Usa este patrón: Título directo. Subtítulo de una línea. 3 bullets con beneficio concreto. Cierre con acción clara. Ahora crea una versión para: [tema]
Workflow recomendado

De prompt rápido a prompt confiable

La mejor práctica no es escribir el prompt perfecto desde el inicio. Es iterar con criterio.

Fase 1

Explora con zero-shot

Comprueba si el modelo entiende la tarea sin demasiada ayuda.

Define rol.
Explica tarea.
Pide formato.
Fase 2

Identifica fallos

Busca dónde se rompe: tono, estructura, criterio, nivel de detalle o categoría.

Marca salidas buenas.
Detecta patrones malos.
Convierte feedback en reglas.
Fase 3

Formaliza con few-shot

Agrega ejemplos representativos para que el modelo copie el patrón correcto.

Incluye casos normales.
Incluye casos límite.
Mantén ejemplos breves.
Buenas prácticas

Lo que más mejora la calidad

Usa ejemplos reales, no ejemplos perfectos de laboratorio

Los ejemplos deben parecerse a los casos que vas a procesar. Si todos son demasiado limpios, el prompt fallará con entradas reales.

Separa claramente entrada y salida

En few-shot, etiqueta cada bloque. Usa “Entrada” y “Salida” para que el patrón sea inequívoco.

No metas ejemplos que contradigan la instrucción

El modelo suele aprender más del patrón que de la explicación. Si un ejemplo está mal, contamina toda la tarea.

Evita prompts largos solo por parecer sofisticados

Más texto no siempre significa más control. Agrega contexto cuando reduzca ambigüedad, no cuando solo decore.

Regla de oro: si puedes describir bien la tarea en una instrucción corta, usa zero-shot.
Sube a few-shot: cuando el output tenga que parecerse a un patrón específico o repetir una decisión de criterio.
Error común: usar ejemplos demasiado parecidos entre sí. Eso puede hacer que el modelo no generalice bien.
Cheat sheet

Decisión rápida

Elige zero-shot si

La tarea es obvia

Resumen, explicación, reescritura simple, lluvia de ideas o transformación directa.

Elige few-shot si

El patrón importa

Clasificación, extracción, estilo editorial, tono de marca o salidas altamente estructuradas.

Combina ambos si

Estás diseñando un flujo

Primero explora con zero-shot. Después convierte las mejores salidas en ejemplos para few-shot.

Conclusión

Zero-shot y few-shot no compiten. Son niveles distintos de contexto. Zero-shot te da velocidad; few-shot te da consistencia. El criterio está en usar el mínimo contexto necesario para que la salida sea útil, clara y repetible.

Empieza con una instrucción directa.
Evalúa si la salida respeta formato, tono y criterio.
Agrega ejemplos solo cuando mejoren la consistencia.
